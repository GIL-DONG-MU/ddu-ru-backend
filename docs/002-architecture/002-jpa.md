# 002. JPA 엔티티 가이드

> 이 문서를 보면 엔티티 작성, 연관관계, 삭제 정책, Querydsl 구현 기준을 파악할 수 있습니다.

---

## 한 줄 요약

엔티티는 `BaseTimeEntity`로 생성/수정 시간을 공유하고, 도메인별로 필요한 연관관계와 삭제 정책을 명시적으로 구현합니다. 복잡한 목록 조회는 Querydsl custom repository를 사용합니다.

---

## 1. 엔티티 기본형

```java
@Entity
@Table(name = "posts")
@Getter
@NoArgsConstructor(access = AccessLevel.PROTECTED)
public class Post extends BaseTimeEntity {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
}
```

기본 규칙:

- 기본 생성자는 `protected`.
- 외부 생성은 정적 팩토리 또는 builder 기반 메서드를 우선 사용합니다.
- 엔티티 필드는 private으로 유지하고, 상태 변경은 의미 있는 메서드로 제공합니다.
- API 응답으로 엔티티를 직접 반환하지 않습니다.

---

## 2. 공통 시간 필드

`BaseTimeEntity`가 제공하는 필드:

| 필드 | 설명 |
|---|---|
| `createdAt` | 생성 시각 |
| `modifiedAt` | 마지막 수정 시각 |

감사 사용자(`createdBy`, `modifiedBy`)는 현재 공통 엔티티에 없습니다.

---

## 3. 연관관계

현재 프로젝트는 JPA 연관관계를 적극적으로 사용합니다.

| 예시 | 관계 |
|---|---|
| `Profile.user` | `@OneToOne(fetch = LAZY)` |
| `Post.user` | `@ManyToOne(fetch = LAZY)` |
| `Post.destination` | `@ManyToOne(fetch = LAZY)` |
| `Participation.post`, `Participation.user` | `@ManyToOne(fetch = LAZY)` |
| `Journey.post` | `@OneToOne(fetch = LAZY)` |
| `JourneyMember.journey`, `JourneyMember.user` | `@ManyToOne(fetch = LAZY)` |
| `ChatRoom.post`, `ChatRoom.journey` | 1:1/1:N 컨텍스트 참조 |
| `ChatMessage.room`, `ChatMessage.sender` | `@ManyToOne(fetch = LAZY)` |

규칙:

- 연관관계는 기본적으로 `LAZY`를 사용합니다.
- Controller 밖으로 엔티티를 그대로 노출하지 않고 DTO로 변환합니다.
- 목록 조회에서 연관 데이터가 필요하면 fetch join, Querydsl projection, batch 조회 중 하나를 명시적으로 선택합니다.

---

## 4. Soft Delete

현재 Soft delete는 공통 추상 메서드가 아니라 도메인별 필드/메서드로 구현합니다.

예:

- `Post.softDelete(Long userId)`
- `JourneyPost`의 `is_deleted`, `deleted_at`, `deleted_by`
- `ChatRoomStatus.DELETED`

새 도메인에서 삭제 기능을 추가할 때 결정할 것:

- 물리 삭제인지, 상태 변경인지, soft delete인지
- 삭제자/삭제 시각이 필요한지
- 목록 조회에서 삭제 데이터를 어떻게 제외할지
- unique 제약과 삭제 데이터가 충돌하지 않는지

---

## 5. Querydsl

목록 검색이나 복합 조건 조회에는 `{Domain}RepositoryCustom` + `{Domain}RepositoryImpl` 패턴을 사용합니다.

예:

- `PostRepositoryCustom`, `PostRepositoryImpl`
- `ParticipationRepositoryCustom`, `ParticipationRepositoryImpl`
- `DestinationRepositoryCustom`, `DestinationRepositoryImpl`

권장 기준:

- 단순 ID 조회/exists/count는 Spring Data JPA 메서드 사용.
- 동적 검색 조건, join, projection이 필요한 목록은 Querydsl 사용.
- API 응답 DTO와 DB query DTO를 분리하면 서비스 조합이 쉬워집니다.
