# 003. 팀 FAQ

> 자주 헷갈리는 코드 배치와 구현 기준을 정리합니다.

---

## DTO는 어디에 두나요?

도메인별 `dto` 하위에 목적별로 둡니다.

```text
post/dto/request
post/dto/response
participation/dto/query
chat/dto/ws
```

---

## Swagger 어노테이션은 Controller에 직접 쓰나요?

현재 패턴은 `*ApiDocs` 인터페이스에 Swagger 문서를 두고, Controller가 이를 구현하는 방식입니다.

```java
public class PostController implements PostApiDocs
```

---

## 성공 응답은 어떤 포맷을 쓰나요?

`ApiResult<T>`를 사용합니다.

- 조회/수정: `ApiResult.ok(data)`
- 생성: `ApiResult.created(data)`
- 삭제 등 본문 없음: `ApiResult.noContent()`

---

## 예외는 `BusinessException(ErrorCode.X)`를 직접 던져도 되나요?

새 비즈니스 예외는 개별 클래스를 만드는 방식을 우선합니다.

```java
throw new PostNotFoundException();
```

단순 validation은 Jakarta Validation과 `GlobalExceptionHandler`에 맡깁니다.

---

## Repository custom 구현은 언제 만드나요?

아래 경우에 만듭니다.

- 검색 조건이 동적입니다.
- 여러 테이블 join/projection이 필요합니다.
- 페이지 목록에서 N+1을 피해야 합니다.

단순 `findById`, `existsBy...`, `countBy...`는 Spring Data JPA 메서드로 충분합니다.

---

## `participations`와 `journey_members`는 어떻게 다른가요?

- `participations`: 모집글에 대한 신청 이력입니다.
- `journey_members`: 승인 이후 실제 여정 워크스페이스 접근 권한입니다.

나의 여정 상세, 그룹 채팅 접근처럼 승인 이후 기능은 `journey_members.status = ACTIVE`를 기준으로 판단합니다.

---

## 1:1 채팅과 그룹 채팅 컨텍스트는 어떻게 구분하나요?

- `PRIVATE`: `post_id`를 참조하고 `journey_id`는 없어야 합니다.
- `GROUP`: `journey_id`를 참조하고 `post_id`는 없어야 합니다.

이 규칙은 `ChatRoom` 도메인 생성 메서드와 DB check constraint에 반영되어 있습니다.

---

## 운영 DB 스키마 변경은 어떻게 하나요?

운영은 Flyway가 켜져 있으므로 `src/main/resources/db/migration`에 다음 버전 SQL을 추가합니다.

자세한 절차는 [Flyway 가이드](../004-operations/004-flyway.md)를 확인합니다.
